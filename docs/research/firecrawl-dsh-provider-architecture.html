Architecture note · provider seam

How @firecrawl/dsh-firecrawl preserves DSH’s native web tools

It is not an MCP bridge and it adds no model-visible tools. It registers search and fetch providers into DSH’s existing ctx.web seam, then pins those providers so the existing web_search and web_fetch tools route to Firecrawl.

What the package actually does

SearchCalls Firecrawl’s /v2/search, maps URLs, titles, snippets, and optional news dates into DSH’s normalized WebSearchResult.
FetchCalls /v2/scrape, maps the returned URL, HTTP status, Markdown or HTML body, and truncation into DSH’s WebFetchResult.
SelectionIts Cordis patch pins both searchProvider and fetchProvider to firecrawl; DSH’s other providers may remain mounted without becoming ambiguous.
ToolsIt owns no model-facing tool definitions. DSH’s existing dsh-tool-web keeps the native names and prompt contract.

Why it is the right structural reference for Organon

Our requirement is the same at the DSH seam: preserve native web_search, avoid a competing generic MCP tool set, and hide transport details behind a provider.

ctx.web.registerSearchProvider(
  OrganonMcpBackedProvider
)

// Internally:
MCPorter runtime → HTTP MCP → search

The difference is the downstream protocol. Firecrawl calls its REST API directly; Organon’s provider should call its private HTTP MCP endpoint. The model-facing contract stays unchanged.

Useful Firecrawl pieces

dsh-firecrawl is a provider-seam reference. @firecrawl/html-extractor is a separate Node/NAPI raw-HTML-to-Markdown library; it does not fetch URLs or render JavaScript.

Firecrawl’s full self-hosted stack can render anonymous JS pages, but it is an operational service with a browser component, not a drop-in library.

Why it is not a drop-in dependency here

The published plugin targets an older DSH release and expects a Firecrawl API key. A private unauthenticated self-hosted Firecrawl deployment is a separate deployment choice, not equivalent to importing the npm package.

For the current Organon design, borrow the seam shape—not its Firecrawl credential and hosted-API assumptions.
