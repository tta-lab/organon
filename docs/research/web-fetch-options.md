# Web-fetch options

**Scope.** Primary-source review of Go extractors and Firecrawl components for a remote HTTP MCP fetch service. “Verified” means stated in the linked repository/docs or visible in the linked source; architecture recommendations are marked **Inference**.

## Go extraction libraries

| Option | Verified facts | Assessment |
|---|---|---|
| [`codeberg.org/readeck/go-readability/v2`](https://codeberg.org/readeck/go-readability/src/branch/v2/README.md) | Maintained fork of `go-shiori/go-readability`, compatible with Mozilla Readability.js 0.6; parses an `io.Reader`/document or fetches a URL; renders cleaned HTML and exposes text/metadata ([API source](https://codeberg.org/readeck/go-readability/src/branch/v2/readability.go)). The original GitHub project is deprecated in favor of this fork ([notice](https://github.com/go-shiori/go-readability)). | Closest Go analogue to Mozilla Readability. It is a parser, not a browser: client-side-rendered content will be absent unless HTML is rendered first. Markdown requires a separate HTML-to-Markdown step. |
| [`github.com/markusmobius/go-trafilatura`](https://github.com/markusmobius/go-trafilatura) | A Go port of Trafilatura with metadata, body text, comments, links/tables/images options, and readability/dom-distiller fallbacks. Its CLI outputs HTML, text, or JSON—not Markdown ([README](https://raw.githubusercontent.com/markusmobius/go-trafilatura/main/README.md), [`go.mod`](https://raw.githubusercontent.com/markusmobius/go-trafilatura/main/go.mod)). The repository has recent main-branch activity ([commit feed](https://github.com/markusmobius/go-trafilatura/commits/main)). | Best candidate if extraction quality and metadata matter more than minimal size; still needs rendering and Markdown conversion. **Inference:** its current Go 1.24 toolchain and sizable dependency/fallback graph make it a less surgical replacement for the existing TypeScript Defuddle path. |
| [`github.com/markusmobius/go-domdistiller`](https://github.com/markusmobius/go-domdistiller) | Standalone Go port of Chromium DOM Distiller; provides `Apply`, `ApplyForReader`, `ApplyForURL`, metadata, text, images, and pagination. Its README says the original DOM Distiller is archived and the Go project omits stylesheet-dependent checks ([README](https://raw.githubusercontent.com/markusmobius/go-domdistiller/main/README.md)). | Useful fallback/benchmark comparator, but weaker maintenance signal than the two options above and also not a JS renderer or Markdown emitter. |

**Conclusion for Go:** use `go-readability/v2` for the smallest Readability-like parser, or evaluate `go-trafilatura` if broader extraction accuracy is worth the added weight. None of these replaces JS rendering; none natively provides the current Defuddle-style Markdown result. The archived [`go-boilerpipe`](https://github.com/jlubawy/go-boilerpipe) explicitly directs users to Trafilatura and should not be selected.

## Firecrawl organization

- [`firecrawl/firecrawl`](https://github.com/firecrawl/firecrawl) is the open-source Firecrawl API/service: its documented core includes scraping URLs to Markdown/HTML, JS-heavy pages, actions, crawling, and search. The official self-hosting guide runs a Docker Compose stack at `http://localhost:3002`; the compose file includes a separate Playwright service ([guide](https://docs.firecrawl.dev/contributing/self-host), [compose](https://github.com/firecrawl/firecrawl/blob/main/docker-compose.yaml)). The guide’s initial local configuration disables API authentication, so this can be an unauthenticated local service on a trusted network—but it is an operationally heavy service, not an embeddable Go extractor.
- [`firecrawl/firecrawl-mcp-server`](https://github.com/firecrawl/firecrawl-mcp-server) is a TypeScript MCP adapter over the Firecrawl API. Its hosted MCP endpoint offers keyless, rate-limited `scrape`, `search`, and `parse`; local Streamable HTTP mode is also supported, with `FIRECRAWL_API_URL` selecting a self-hosted Firecrawl instance ([configuration/source README](https://raw.githubusercontent.com/firecrawl/firecrawl-mcp-server/main/README.md)). **Verified distinction:** keyless hosted access is anonymous only in the limited/rate-limited sense; self-hosting avoids a hosted key but still requires operating Firecrawl.
- The official [`apps/go-sdk`](https://github.com/firecrawl/firecrawl/tree/main/apps/go-sdk) is a reusable Go **HTTP client**, not a local extractor or renderer. Its `NewClient` accepts a custom API URL and its `Scrape` method calls `/v2/scrape` ([source](https://github.com/firecrawl/firecrawl/blob/main/apps/go-sdk/firecrawl.go)); therefore it can target a self-hosted Firecrawl API, but JS execution and extraction remain server-side. The monorepo states that SDKs are MIT-licensed while the main service is primarily AGPL-3.0 ([license note](https://github.com/firecrawl/firecrawl#license)).
- [`firecrawl/html-extractor`](https://github.com/firecrawl/html-extractor) is a local Rust main-content extractor with Node/NAPI bindings and Markdown output. It is not Go, does not fetch or execute JavaScript, and is separate from the Firecrawl service.
- [`firecrawl/dsh-firecrawl`](https://github.com/firecrawl/dsh-firecrawl) is a DSH plugin that points both built-in `web_search` and `web_fetch` at Firecrawl ([README](https://github.com/firecrawl/dsh-firecrawl)). It is integration precedent, not a Go library, and adopting it wholesale would conflict with the project requirement to retain its native search-provider override.

## Recommendation

**Inference:** build the proposed remote HTTP MCP fetch server in TypeScript and keep DSH’s native `WebSearchProvider` override unchanged. Let the server own URL validation/SSRF policy, HTTP limits, optional Playwright rendering, Defuddle extraction, Markdown normalization, caching, and MCP transport; expose fetch only through that seam. This preserves the project’s existing search-provider selection while adding a JS-capable fetch boundary.

Use Firecrawl as an optional deployment/backend choice rather than as the embedded implementation: self-hosted Firecrawl is the strongest off-the-shelf option when anonymous local JS rendering and broad anti-bot/browser behavior justify Docker, Redis/Postgres/Playwright operations; hosted keyless MCP is suitable for experimentation but introduces rate limits and an external data path. If a future Go-native implementation is required, start with `go-readability/v2` (or benchmark `go-trafilatura`) after rendering, and treat the Firecrawl Go SDK only as a client to a running Firecrawl service.
